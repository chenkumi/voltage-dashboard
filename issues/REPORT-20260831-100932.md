### BUG-003: 瀏覽器停用 Storage API 時整個應用程式無法掛載

- 嚴重度: S1
- 資安相關: 否
- 位置: `src/app/theme.tsx:58-64,101-104`（`ThemeProvider`）
- 描述: ThemeProvider 的 state initializer 直接呼叫 `localStorage.getItem()`，主題切換與 D 快捷鍵直接呼叫 `setItem()`，均未處理 `SecurityError`。ThemeProvider 位於 RouterProvider 外層，且專案沒有 Error Boundary；Storage 被瀏覽器政策、sandbox 或隱私設定拒絕時，所有頁面都無法掛載。相同專案的 i18n 儲存邏輯已有安全 fallback，ThemeProvider 沒有。
- 重現步驟:
  1. 在隔離 jsdom 或受限制瀏覽器中令 `window.localStorage.getItem()` 拋出 `SecurityError`。
  2. Render `ThemeProvider` 與任意 child。
  3. 觀察例外從 state initializer 穿透，child 與 Router 均未渲染。
- 可重現等級: T1
- 受影響範圍: 應用程式根層 1 處，阻斷全部頁面；主題切換另有 2 個未處理 `setItem()` 呼叫點
- 驗證結果: 已確認
- 備註: 隔離 component test 已直接重現。

### BUG-005: Reload 後所有已儲存報表仍可點擊，但必然無法開啟

- 嚴重度: S1
- 資安相關: 否
- 位置: `src/app/webmcp/reporting/report-library.ts:25-46`、`src/app/webmcp/reporting/reporting-tools.ts:606-619,722-749`、`src/app/webmcp/reporting/report-canvas.tsx:396-416`
- 描述: Report library 將含舊 `contextId` 的 snapshot 存入 IndexedDB，reload 後的新 Reporting runtime 無條件產生新的隨機 `contextId`。UI 仍將舊紀錄列為可開啟，但 `loadSavedReport()` 一定以 `SQLITE_CONTEXT_MISMATCH` 拒絕，且沒有安全重建 evidence 或清理失效項目的流程。
- 重現步驟:
  1. 建立報表並等待 Canvas 自動儲存至 IndexedDB。
  2. Reload Dashboard，使新 controller 建立新的 context。
  3. 在 Saved reports 點擊原報表。
  4. 觀察 report 無法載入，UI 只顯示一般開啟失敗訊息。
- 可重現等級: T1
- 受影響範圍: 1 條 persisted-report reload/open 流程；所有跨 reload／新 Provider context 的已儲存報表
- 驗證結果: 已確認
- 備註: 既有 reporting tests 已確認 rebuilt context 必拒絕 snapshot，且只有同一 context 能 restore。跨 context 拒絕本身是正確安全邊界；問題是持久化 library 的保存、列出與開啟產品契約互相矛盾。

### BUG-006: 新增退貨頁切換 orderId 後，UI、草稿與 verifier 指向不同訂單

- 嚴重度: S1
- 資安相關: 否
- 位置: `src/app/webmcp/returns/return-pages.tsx:511-528,604-624`（`ReturnAddPage`）、`src/app/webmcp/returns/return-tools.ts:659-666`
- 描述: URL 的 `orderId` 會更新，但 form state 只在 component 初次 mount 初始化。React Router 重用 `/returns/add` element 時，畫面已顯示訂單 B，editor/controller 仍保留訂單 A 的 items。對 B 使用 WebMCP 草稿工具會被 route mismatch 拒絕；UI 提交則以 B 的 order ID 搭配 A 的 order line，遭 repository 拒絕。
- 重現步驟:
  1. 開啟 `/returns/add?orderId=A`，選取 A 的退貨品項並確認 verifier 為 A。
  2. 不 reload，導覽至 `/returns/add?orderId=B`。
  3. 觀察畫面已顯示 B，但 `get_return_form_state` 仍回 A。
  4. 對 B 套用草稿或由 UI 提交；前者回 route mismatch，後者回品項不屬於所選訂單。
- 可重現等級: T1
- 受影響範圍: 1 個 `/returns/add` route；所有 Agent 連續導覽、history navigation 或 query-string 切換訂單的流程
- 驗證結果: 已確認
- 備註: 隔離 route-switch test 已同時驗證畫面、verifier、tool 與 repository 拒絕結果。

### BUG-009: 商品編輯路由切換後，舊 editor session 仍可接受下一筆草稿

- 嚴重度: S2-2
- 資安相關: 否
- 位置: `src/app/webmcp/products/product-tools.ts:610-618`（`open_product_edit`／`apply_product_editor_draft`）、`src/app/webmcp/products/product-editor-controller.ts:28-33`
- 描述: `open_product_edit` 觸發非同步 route navigation 後立即回傳 OK；草稿工具不帶目標 productId，也不確認新 route session 已 attach。Agent 連續呼叫「開啟商品 B → 套用草稿」時，第二步可成功寫入仍綁定商品 A 的暫存狀態，route commit 後才切至 B。
- 重現步驟:
  1. 在 `/products/edit/1` 確認 controller 綁定商品 1。
  2. 呼叫 `open_product_edit({ productId: 2 })`。
  3. 不等待 route re-render，立即呼叫 state verifier 或 apply draft。
  4. 觀察呼叫仍回傳／修改商品 1，稍後才變成商品 2。
- 可重現等級: T1
- 受影響範圍: 從一個 edit route 切到另一商品時的 2 個連續 WebMCP editor 操作
- 驗證結果: 已確認
- 備註: S2-2 分類不完全貼合，建議補類「非同步導覽／陳舊 UI session 競態」。Agent 不會自動儲存，但使用者可能誤存已被填入錯商品的草稿。

### BUG-008: Inventory 與 Orders 長流程 UI tests 的 5 秒等待預算不可靠

### BUG-001: Dashboard Revenue 將所有付款結果的訂單總額相加

- 嚴重度: S3
- 資安相關: 否
- 位置: `src/app/webmcp/voltage-admin-data.ts:26-35`（`getVoltageAdminDashboard`）
- 描述: `revenueByCurrency` 只依幣別篩選後加總所有訂單，沒有排除 pending、failed 或 refunded。固定 seed 中 Dashboard 顯示 240,660.70 USD，但 paid-only 僅 115,045.23 USD，非 paid 金額占 52.2%。不過 UI detail 明寫「Order totals by currency」，現有契約不足以判定此卡一定應採 paid-only，因此降級為語意推測。
- 重現步驟:
  1. 使用既有 seed 建立 Commerce snapshot。
  2. 分別計算所有 orders 與 `paymentStatus === "paid"` 的總額。

- 可重現等級: T1
- 受影響範圍: Dashboard Revenue metric 與 `get_voltage_admin_dashboard` tool 共 2 處下游
- 驗證結果: 無法重現，降級為推測
- 備註: 行為可穩定重現，但產品語意有歧義；若 KPI 定義為已收款／已認列營收即為數值錯誤，若定義為 gross order total 則只剩主標題不精確。分類不完全貼合，建議補類「營運指標語意／命名契約不明確」。
