### BUG-001: Dashboard「Revenue」將失敗、待付款與已退款訂單全部計入

- 嚴重度: S3
- 資安相關: 否
- 位置: `src/app/webmcp/voltage-admin-data.ts:26`（`getVoltageAdminDashboard`）
- 描述: `revenueByCurrency` 只依幣別篩選後加總所有訂單總額，未依 `paymentStatus` 排除 `pending`、`failed`、`refunded`。UI 與 WebMCP 將此欄位命名為 Revenue，會把未實現或已退回金額呈現成營收。
- 重現步驟:
  1. 建立同幣別、不同付款結果的 Commerce snapshot。
  2. 呼叫 `getVoltageAdminDashboard` 並比較 `revenueByCurrency` 與 paid 訂單總額。
- 可重現等級: T1
- 受影響範圍: Dashboard Revenue metric 與 `get_voltage_admin_dashboard` WebMCP tool 共 2 處下游
- 驗證結果: 無法重現，降級為推測
- 備註: 隔離計算確認 seed 顯示 240,660.70 USD，其中 paid-only 僅 115,045.23 USD，非 paid 佔 52.2%；但 UI detail 明寫「Order totals by currency」，現有契約不足以排除刻意顯示 gross order total。分類不完全貼合，建議補類「營運指標語意／命名契約不明確」。

### BUG-002: WebMCP 導覽狀態永遠宣稱無法前進且導覽回應使用舊頁面

- 嚴重度: S3

- 重現步驟:

  2. 呼叫 `navigate_state`，觀察 `canGoForward` 仍為 false。
  3. 呼叫 `navigate_forward` 或 `navigate_back`，比較回應 page 與 router 最終 pathname。
- 可重現等級: T1

- 驗證結果: 已確認

### BUG-003: 停用瀏覽器儲存空間時 ThemeProvider 會阻斷整個應用程式渲染

- 嚴重度: S1
- 資安相關: 否
- 位置: `src/app/theme.tsx:58`（`ThemeProvider` 初始化與 `setTheme`）
- 描述: ThemeProvider 直接存取 `localStorage.getItem/setItem`，沒有像 i18n 儲存邏輯一樣提供例外 fallback。當瀏覽器政策、sandbox 或隱私設定令 Storage API 丟出 `SecurityError` 時，初始 render 直接失敗。
- 重現步驟:
  1. 在 jsdom 或受限制瀏覽器中令 `window.localStorage` 存取拋出 `SecurityError`。
  2. render `ThemeProvider`。
  3. 觀察例外穿透並使應用程式無法掛載。
- 可重現等級: T1
- 受影響範圍: 應用程式根層 1 處，阻斷全部頁面
- 驗證結果: 已確認
- 備註: 隔離 test 確認 `localStorage.getItem()` 的 `SecurityError` 會從 state initializer 穿透；ThemeProvider 位於 RouterProvider 外層且專案沒有 Error Boundary，全部頁面無法掛載。`setItem()` 在主題切換與 D 快捷鍵也會產生未處理錯誤。

### BUG-005: Reload 後的已儲存報表仍可點擊但必然無法載入
