# Plan

建立 Smart Dashboard 第一階段的 SQLite3 WASM 基礎垂直切片，讓 Voltage
Market Admin iframe 能以同一個 WebMCP Agent 核心安全執行通用唯讀 SQL，完成後
即可在不增加領域專用查詢 tools 的情況下探索 curated 營運資料。實作先驗證
Worker、Vite/WASM asset、SQL 安全政策、iframe lifecycle 與 WebMCP executor 的
端到端接線，再以這個穩定介面支撐後續 skills 與 Report Canvas。

> 本計畫請使用 execute-plan 技能執行。Checkbox（`- [ ]`）語法為追蹤格式。

## Scope

- In:
  - 使用既有 `@sqlite.org/sqlite-wasm@3.53.0-build1` 建立專案自有的 module
    Worker 與 `:memory:` database runtime。
  - 建立不含個資與付款資料的 deterministic curated reporting datasets。
  - 實作單一 `execute_readonly_sql` WebMCP tool，支援參數、欄位資訊、列數、
    截斷狀態與執行時間。
  - 以 executor 與 SQLite query-only 模式共同限制 SQL 為單一唯讀查詢。
  - 將 runtime lifecycle 綁定 Voltage Admin iframe，保留原生 WebMCP 與
    same-origin test provider 兩條既有註冊路徑。
  - 驗證 Vite dev、production build/preview、WebMCP discovery、tool execution、
    iframe 切換與資源釋放。
- Out:
  - Report Canvas、widget、`queryId` cache 與報表持久化。
  - sales、inventory、report-authoring 等完整 skills 內容。
  - OPFS、IndexedDB database persistence、跨來源資料匯入與正式資料同步。
  - 發布、寄送、分享報表或任何外部高風險副作用。
  - 移除或重寫現有 Voltage Admin 功能與 tools。

## Research basis

- 專案已安裝 `@sqlite.org/sqlite-wasm@3.53.0-build1`，Node.js
  `v24.15.0` 符合套件 `node >=22` 要求。
- SQLite 官方 WASM API 支援 OO1 與獨立 Worker；套件目前將 Worker1／
  Promiser1 標示為 deprecated，因此使用 Vite module Worker，在 Worker 內直接初始化
  OO1 database。
- 目前 `vite.config.ts` 尚未設定 SQLite WASM 的 bundler 選項，必須同時驗證
  dev 與 production build/preview，避免只在 dev 可解析 WASM asset。
- Voltage Admin 已透過 `__webmcpReady` 等待非同步 tool registration，並同時支援
  `document.modelContext.registerTool()` 與 `__webmcpTestProvider`，可沿用既有接點。
- 現有 Vitest 以 Node 環境執行；純 TypeScript policy 與資料契約採 Tier 1 測試，
  真實 Worker/WASM asset 與 iframe 整合採 Tier 2 瀏覽器驗證。

## Files

- `package.json`：保留既有 SQLite WASM 依賴，不重複安裝或改版。
- `package-lock.json`：保留依賴鎖定結果。
- `vite.config.ts`：只加入經 dev/build/preview 驗證確有需要的 SQLite WASM bundler
  設定，不引入 OPFS headers。
- `src/app/webmcp/reporting/types.ts`：定義 worker protocol、SQL request/result、
  normalized value 與 runtime 狀態。
- `src/app/webmcp/reporting/reporting-data.ts`：定義 deterministic、匿名化的 curated
  schema 與 seed 資料。
- `src/app/webmcp/reporting/sql-policy.ts`：實作單一唯讀 statement、允許 schema、
  SQL/輸出限制與標準錯誤分類。
- `src/app/webmcp/reporting/sqlite-worker.ts`：初始化 SQLite WASM、建立/seed
  `:memory:` database、啟用 query-only 並執行受控查詢。
- `src/app/webmcp/reporting/sqlite-runtime.ts`：管理 Worker request correlation、
  初始化、abort、dispose 與錯誤正規化。
- `src/app/webmcp/reporting/reporting-tools.ts`：定義 `execute_readonly_sql` tool 與
  runtime adapter。
- `src/app/webmcp/reporting/*.test.ts`：驗證 SQL policy、資料邊界、結果正規化與
  runtime protocol。
- `src/app/webmcp/voltage-admin.tsx`：建立 reporting runtime、註冊 SQL tool、執行
  tool 並在 iframe unmount 時 dispose。
- `src/app/webmcp/commerce-safety.test.ts`：擴充 SQL tool 的個資與副作用邊界測試。
- `docs/SMART-DASHBOARD.md`：若實作驗證導致介面調整，同步記錄第一階段實際契約。
