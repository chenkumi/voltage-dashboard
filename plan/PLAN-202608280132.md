# Plan

建立 Smart Dashboard 第二階段的最小報表協作垂直切片，讓同一個 WebMCP Agent 能載入資料語意 skills、執行 SQL、以 `queryId` 引用查詢結果，再建立可由使用者直接編輯的結構化報表。完成後，Admin 將從安全資料探索工具進化為真正可展示「使用者與 Agent 共同創造」的智慧報表工作台。

> 本計畫請使用 execute-plan 技能執行。Checkbox（`- [ ]`）語法為追蹤格式。

## Scope

- In:
  - 建立 sales、inventory、report-authoring 三組 Admin skills。
  - 將現有 inline skill definitions 抽離為可測試的 skill registry。
  - 建立 iframe-local query result cache，讓 SQL 結果取得穩定 `queryId`。
  - 建立單一 active report 的 memory-only state。
  - 提供建立、讀取、修改、移除與排序 widgets 的 WebMCP tools。
  - 支援 KPI、table、safe Markdown text 與 bar chart widgets。
  - 在 Voltage Admin 新增可由 Agent 與使用者共同編輯的 Report Canvas。
  - 完成一條「資料狀態 → SQL → queryId → report widgets → 人工修改」展示流程。
  - 維持現有 SQL、個資、付款、iframe lifecycle 與 thread 隔離邊界。
- Out:
  - IndexedDB、OPFS 或伺服器端報表持久化。
  - 多份報表管理、多人協作、分享、發布或寄送。
  - 任意 HTML、React、JavaScript、SQL extension 或自訂 widget 程式碼。
  - drag-and-drop layout、自由尺寸網格與完整圖表編輯器。
  - line、pie、stacked-bar 等更多圖表種類。
  - 自動匯入外部資料或跨來源 database。
  - 將 SQLite、query cache 或 report state 移入 host Agent core。

## Design basis

- 以 `docs/SMART-DASHBOARD.md` 第 6–11 節的 skills、report model、tools 與協作流程作為已確認的介面草稿。
- 第一版只保留一份 iframe-local active report；iframe teardown 後資料全部清除。
- Query cache 最多保存 32 筆結果、總序列化容量 8 MiB；達到上限時安全拒絕新結果，不淘汰已被 widget 引用的資料。
- Query cache 第一版不設定 TTL，生命週期與 Admin iframe 相同，避免報表在展示期間因時間到期失效。
- Report Canvas 支援 KPI、table、text、bar 四種宣告式 widgets，不執行任意生成程式碼。
- 使用者可以直接修改 report/widget 標題、刪除與重新排序 widgets；Agent 透過 WebMCP tools 修改相同 state。
